# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives

### 1.1 Summary of Objectives

We are addressing a critical state-synchronization regression in **Chunk 3 (`StepSequencer.tsx`)**:

1. **"Musical Chairs" Bar Overwrite Bug (`StepSequencer.tsx`):** When clicking anywhere inside a bar on the expanded timeline (`.staff-canvas-area`), the GUI overwrites the chord of the bar the user is *leaving* with the chord of the bar being *selected*. This regression does not occur when clicking chord symbol pills or individual note hitboxes.
2. **Canvas Click-Away Deselection (`StepSequencer.tsx` & `NotationCanvas.tsx`):** Clicking empty staff space away from noteheads inside a bar should deselect any currently selected notes without modifying the chord's stored pitches, establishing parity with `NotationCanvas.tsx`.

### 1.2 Root Cause Analysis

* **Why Clicking the Staff Area Played "Musical Chairs" with Chords:**
* In `StepSequencer.tsx`, the `handlePointerDown` handler for the sequencer canvas (`seqCanvasRef`, lines 630–670) executed in the following order:
```typescript
if (startStep === -1) return;

// 1. DESELECT NOTES ON CLICK-AWAY
const hasModifier = e.shiftKey || e.metaKey || e.ctrlKey || e.altKey;
if (!hasModifier && sequenceRef.current[startStep]) {
  updateActiveNotes(sequenceRef.current[startStep].notes || [], true, false, []);
}

// ... pointer capture & marquee tracking ...

// 2. UPDATE ACTIVE STEP REF AT THE VERY END
setSelectedStep(startStep);
selectedStepRef.current = startStep;

```


* **The Race Condition:** When `updateActiveNotes` is called, `MIDIProvider` updates its active chord state and synchronously broadcasts a `MIDI_MESSAGE_RECEIVED` event with `{ refresh: true, notes: newBarNotes }`.
* Because `selectedStepRef.current = startStep` had not yet executed, `selectedStepRef.current` still pointed to the **previous bar index** (the bar being left).
* The `MIDI_MESSAGE_RECEIVED` event listener in `StepSequencer.tsx` (lines 280–290) intercepted `{ refresh: true }` and executed:
```typescript
setSequence((prev: any[]) => {
  const next = [...prev];
  next[selectedStepRef.current!] = { notes: [...currentNotes], symbol };
  return next;
});

```


* Consequently, the sequencer overwrote `sequence[oldStep]` with `sequence[newStep].notes`, destroying the chord in the bar being left.


* **Why Clicking Chord Symbol Pills Did Not Have This Bug:**
* In the Chord Symbol Pill `onPointerDown` handler (lines 450–460), `setSelectedStep(idx); selectedStepRef.current = idx;` is explicitly invoked **before** `updateActiveNotes(bar.notes, true, true);`. Thus, any resulting `{ refresh: true }` broadcast targets `selectedStepRef.current === idx` (an identity update), leaving previous bars untouched.

## 2. Technical Decisions & Dependencies

### 2.1 Architectural Decisions & Zero-Drift Alignment

* **Order of Operations Enforcement in `handlePointerDown`:** We must hoist `setSelectedStep(startStep); selectedStepRef.current = startStep;` to execute immediately after resolving `startStep`, **before** calling `updateActiveNotes(...)`.
* **Click-Away Deselection Parity:** By setting `selectedStepRef.current = startStep` first, calling `updateActiveNotes(sequenceRef.current[startStep].notes || [], true, false, [])` safely clears `selectedNotes` to `[]` and syncs the new bar's notes to the main workspace without overwriting the previous bar.

### 2.2 Pseudo-Code Specification

```typescript
const handlePointerDown = (e: React.PointerEvent) => {
  // ... early returns for buttons, note hitboxes, chord pills, and Write Mode ...

  const stepEl = elem?.closest('[data-step-index]');
  let startStep = -1;
  if (stepEl) {
    startStep = parseInt(stepEl.getAttribute('data-step-index') || '', 10);
  }
  
  if (startStep === -1) return;

  // 1. MANDATORY: UPDATE SELECTED STEP REF FIRST TO PREVENT BAR OVERWRITES
  setSelectedStep(startStep);
  selectedStepRef.current = startStep;

  // 2. PARITY WITH NOTATION CANVAS: Deselect notes when clicking away without modifiers
  const hasModifier = e.shiftKey || e.metaKey || e.ctrlKey || e.altKey;
  if (!hasModifier && sequenceRef.current[startStep]) {
    updateActiveNotes(sequenceRef.current[startStep].notes || [], true, false, []);
  }

  e.currentTarget.setPointerCapture(e.pointerId);
  // ... initialize marquee drag tracking ...
};

```
