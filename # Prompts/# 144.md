
# Product Requirements Prompt (PRP) — [Status Marker] ✅

## 1. Project Context & Objectives
In the Chord Notator module (`src/plugins/chord-notator/`), the timeline (`StepSequencer.tsx`) suffers from critical event-collision bugs that destroy user interaction parity with the main notation canvas:

1. **Write Mode Hitbox Interference (Dropped Notes):** When attempting to add a note a 3rd above/below an existing note, the invisible `w-6 h-6` interaction hitbox of the existing note intercepts the `pointerdown` event, preventing the click from reaching the `.staff-canvas-area`. Note hitboxes must be disabled (`pointer-events-none`) whenever Write Mode is active.
2. **Global Undo Stack Collision:** Pressing `Cmd+Z` while focused on the timeline causes the main `NotationCanvas` to pop history states from completely different bars, corrupting the active step. The timeline must implement its own `seqUndoStack`, and intercept `Cmd+Z` using `{ capture: true }` to stop propagation to the main canvas.
3. **Redundant Arrow Key Handlers:** `StepSequencer.tsx` is redundantly listening for `ArrowUp` and `ArrowDown`, which collides with the global handlers in `NotationCanvas.tsx`. This causes rogue transpositions and double audio triggers. All vertical arrow logic must be completely deleted from the timeline, deferring entirely to the original `NotationCanvas` logic.

## 2. Technical Decisions & Architectural Fixes

### A. Disable Note Hitboxes in Write Mode
Use a React ref or state check to disable pointer events on note hitboxes during Write Mode.
```tsx
{/* Inside renderedNotes.map in StepSequencer.tsx */}
<div 
  data-seq-note={n.note}
  data-seq-step={idx}
  className={`absolute top-1/2 left-1/2 w-6 h-6 -translate-x-1/2 -translate-y-1/2 z-50 rounded-full ${
    isExpanded && !isWriteModeRef.current ? 'pointer-events-auto cursor-pointer' : 'pointer-events-none'
  }`}
  onPointerDown={...}
/>

```

### B. Event Capture for Timeline Undo/Redo

Attach a capture-phase listener to the window so the timeline intercepts `Cmd+Z` before `NotationCanvas.tsx` can react and corrupt the state.

```tsx
const handleKeyCapture = (e: KeyboardEvent) => {
  if (!isExpandedRef.current) return;
  if ((e.metaKey || e.ctrlKey) && (e.key === 'z' || e.key === 'Z')) {
    e.stopImmediatePropagation();
    e.preventDefault();
    if (e.shiftKey) redoSeq();
    else undoSeq();
  }
};
// Must use capture: true to intercept before NotationCanvas
window.addEventListener('keydown', handleKeyCapture, { capture: true });
return () => window.removeEventListener('keydown', handleKeyCapture, { capture: true });

```

### C. Purge Redundant Vertical Arrow Logic

Remove `ArrowUp` and `ArrowDown` entirely from `handleKey` in `StepSequencer.tsx`. `NotationCanvas.tsx` already handles selection traversal globally, which inherently syncs with `selectedNotes` context.
