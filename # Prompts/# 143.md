# Product Requirements Prompt (PRP) — [Status Marker] ✅

## 1. Project Context & Objectives

In the Chord Notator module (`src/plugins/chord-notator/`), the timeline (`StepSequencer.tsx`) currently suffers from severe functional bugs (dropped click inputs, corrupted undo history, and arrow keys moving/double-playing notes).

**The Root Architectural Failure:**
`NotationCanvas.tsx` and `StepSequencer.tsx` are both mounted simultaneously and both attach global `window.addEventListener('keydown')` listeners for `ArrowUp`, `ArrowDown`, `Cmd+Z`, `Backspace`, etc.
When a key is pressed, **both components execute their logic simultaneously**.

1. `NotationCanvas` handles the keystroke, updates its `activeNotes`, and calls `updateActiveNotes`.
2. `StepSequencer` intercepts that sync via `MIDI_MESSAGE_RECEIVED` and saves it to the sequence.
3. *However*, `StepSequencer` was *also* executing its own redundant, conflicting `keydown` logic and its own redundant `seqUndoStack`, causing double-execution, rogue transpositions, playing 2 notes at once, and history corruption.

Furthermore, `StepSequencer` failed to capture click-to-write note entries reliably because it relied on asynchronous React state for ghost note hover positions, whereas the original `NotationCanvas` correctly uses synchronous direct-DOM manipulation for zero-latency note entry.

**Objective:**
Rip out all redundant global key listeners and duplicate undo stacks from `StepSequencer.tsx`. Let the main notation handle editing, which automatically bi-directionally syncs back to the timeline. Clone the exact direct-DOM ghost note logic from `NotationCanvas.tsx` into the timeline for flawless click entry.

## 2. Technical Decisions & Dependencies

### A. Eradicate Global Event Collisions

`StepSequencer.tsx` MUST NOT listen to `ArrowUp`, `ArrowDown`, `Cmd+Z`, `Cmd+Shift+Z`, `Backspace`, or `Delete`.
All of these are already handled globally by `NotationCanvas.tsx`, which broadcasts changes via `updateActiveNotes`. `StepSequencer` already seamlessly saves these changes to the active step via its existing `MIDI_MESSAGE_RECEIVED` listener block.

* **Keep** `ArrowLeft` and `ArrowRight` exclusively for navigating timeline steps.
* **Keep** `Escape` to toggle `setIsWriteMode(false)`.

### B. Exact Port of Direct-DOM Write Mode

Rip out all React hover states (`ghostStepOffset`, `ghostSnappedY`, `ghostIsOutOfBounds`, `ghostBarIndex`, `ghostAccidental`) from `StepSequencer.tsx`.
Inject a single `#timeline-ghost-note` element inside the timeline container, and manipulate its styles directly on `onPointerMove`, exactly mimicking `NotationCanvas.tsx`:

```tsx
// Exact math clone from NotationCanvas.tsx
const snapTimelineGhostNote = (clientY: number, rect: DOMRect, currentStaffSpace: number, keySignature: string, accidental: any, lut: any[]) => {
  const pointerY = clientY - rect.top;
  const canvasCenterY = rect.height / 2;
  const relativeY = canvasCenterY - pointerY;
  let stepOffset = 0;

  if (relativeY >= 0) {
      stepOffset = Math.round((relativeY - currentStaffSpace) / (currentStaffSpace / 2));
  } else {
      stepOffset = Math.round((relativeY + currentStaffSpace) / (currentStaffSpace / 2));
  }

  const snappedY = canvasCenterY - (((stepOffset) * (currentStaffSpace / 2)) + (relativeY >= 0 ? currentStaffSpace : -currentStaffSpace));

  const ghost = document.getElementById('timeline-ghost-note');
  if (ghost) {
      ghost.classList.remove('hidden');
      ghost.style.top = `${snappedY}px`;
      (ghost as any).dataset.step = stepOffset.toString();
      
      const { midiNote, accidental: calcAcc } = calculateWriteModePitch(stepOffset, keySignature, accidental, lut);
      (ghost as any).dataset.midiNote = midiNote.toString();
      (ghost as any).dataset.accidental = calcAcc === null ? 'null' : calcAcc;
      
      const accElement = document.getElementById('timeline-ghost-accidental');
      if (accElement) accElement.textContent = calcAcc || '';
  }
};

```
