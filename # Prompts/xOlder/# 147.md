# Product Requirements Prompt (PRP) — [Status Marker] ✅ Completed

## 1. Project Context & Objectives

In the Chord Notator module (`src/plugins/chord-notator/`), Chunk 1 of the Master Backlog targets two critical functional regressions in the main interactive notation canvas (`src/plugins/chord-notator/components/NotationCanvas.tsx`):

1. **Main Notation Undo/Redo Regression:** The main notation canvas is no longer responding to undo/redo commands (`Cmd+Z`, `Ctrl+Z`, `Cmd+Shift+Z`, `Ctrl+Y`). This regression stems from global event listener interference and/or state synchronization where incoming `refresh: true` MIDI/app events replace `activeNotes.current` without preserving the chronological integrity of `undoStack` and `redoStack`. We must restore reliable history traversal across both keyboard shortcuts and custom `APP_HISTORY` window events.


2. **Ottava (`8va`/`15ma`/`8vb`/`15mb`) Write Mode Pitch Offset Bug:** When adding notes via mouse click in Write Mode while an active octave shift (`8va`, `15ma`, `8vb`, or `15mb`) is rendered on the staff, the newly inserted note is incorrect by 1 or 2 octaves. Currently, `snapGhostNote` and `handlePointerDown` convert the cursor's Y-coordinate into a **visual step offset** and pass that unadjusted step directly to `calculateWriteModePitch`. Because `recalculateLayout` applies a `-7`/`-14` (`8va`/`15ma`) or `+7`/`+14` (`8vb`/`15mb`) vertical shift to notes in extreme registers, clicking a visual staff position under an ottava marking must mathematically invert the active shift to resolve the intended logical pitch.

## 2. Technical Decisions & Dependencies

### Component State & References (`NotationCanvas.tsx`)

* **`activeTrebleShiftRef` (`useRef<number>(0)`):** Tracks the currently active treble ottava displacement (`0`, `-7` for `8va`, or `-14` for `15ma`).


* **`activeBassShiftRef` (`useRef<number>(0)`):** Tracks the currently active bass ottava displacement (`0`, `+7` for `8vb`, or `+14` for `15mb`).


* **`undoStack` & `redoStack` (`useRef<ActiveNoteData[][]>`):** Mutable history stacks storing deep-cloned snapshots of `activeNotes.current` (capped at 50 states).

### Mathematical Formulas & Algorithmic Specifications

#### 1. Ottava Shift Inversion Algorithm

When `recalculateLayout()` executes in `NotationCanvas.tsx`, it computes `trebleShift` and `bassShift` to bring extreme registers onto the visible staff. We store these values in refs:

```tsx
activeTrebleShiftRef.current = trebleShift;
activeBassShiftRef.current = bassShift;

```

When a user hovers or clicks in Write Mode, the raw Y-coordinate relative to the staff center ($Y = 0$, Middle C) yields a visual step offset ($\text{visualStep}$):

$$\text{visualStep} = \text{Math.round}\left(\frac{\text{relativeY} \pm \text{staffSpace}}{\text{staffSpace} / 2}\right)$$

To determine the intended **logical step offset** ($\text{logicalStepOffset}$), we check whether the click occurred in the treble region ($\text{visualStep} \ge -2$) or bass region ($\text{visualStep} < -2$) and subtract the corresponding active shift:

$$\text{activeShift} = \begin{cases}  \text{activeTrebleShiftRef.current} & \text{if } \text{visualStep} \ge -2 \\ \text{activeBassShiftRef.current} & \text{if } \text{visualStep} < -2  \end{cases}$$

$$\text{logicalStepOffset} = \text{visualStep} - \text{activeShift}$$

For example, if a treble `8va` line is active ($\text{activeShift} = -7$) and the user clicks the visual E5 space ($\text{visualStep} = 9$), the calculation yields:

$$\text{logicalStepOffset} = 9 - (-7) = 16 \quad (\text{E6, MIDI 88})$$

This $\text{logicalStepOffset}$ is passed directly to `calculateWriteModePitch(logicalStepOffset, keySignatureRef.current, accidentalOverrideRef.current, lutRef.current)`, ensuring both the ghost notehead preview and the committed note represent the correct octave.

```tsx
// Helper function for offset inversion in NotationCanvas.tsx
const getLogicalWriteModeStep = (visualStep: number): number => {
  const isTrebleRegion = visualStep >= -2;
  const activeShift = isTrebleRegion ? activeTrebleShiftRef.current : activeBassShiftRef.current;
  return visualStep - activeShift;
};

```

#### 2. History Stack Integrity & Event Reconciliation

To ensure `Cmd+Z` / `Ctrl+Z` reliably undoes edits on `NotationCanvas.tsx`:

1. **Deep-Cloning Snapshots:** `commitState()` must push `JSON.parse(JSON.stringify(activeNotes.current))` to `undoStack.current` to prevent object reference mutations from corrupting historical states.


2. **Global Event Priority:** `handleKeyDown` in `NotationCanvas.tsx` must execute `e.preventDefault()` and `e.stopPropagation()` when handling `Cmd+Z` (`!e.shiftKey`) or `Cmd+Shift+Z` / `Ctrl+Y`.


3. **Refresh Protection:** When `undo()` or `redo()` invokes `updateActiveNotes([...activeNotes.current])`, the broadcast `MIDI_MESSAGE_RECEIVED` event with `refresh: true` must not clear or alter `undoStack.current` or `redoStack.current`.
