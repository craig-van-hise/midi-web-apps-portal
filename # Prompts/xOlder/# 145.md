# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives

### 1.1 Summary of Objectives

The **VV | MIDI Chord Notator & Sequencer** suite (`src/plugins/chord-notator/`) provides real-time sheet music rendering and interactive notation editing. Currently, two critical defects in the primary notation editor (`src/plugins/chord-notator/components/NotationCanvas.tsx`) impede user workflow:

1. **Broken Undo/Redo History Traversal:** The notation canvas fails to respond reliably to standard keyboard shortcuts (`Cmd+Z`, `Ctrl+Z`, `Cmd+Shift+Z`, `Cmd+Y`) and global `APP_HISTORY` custom events. State pops from `undoStack` and `redoStack` do not trigger React re-renders, leaving the visual canvas out of sync with internal history state.
2. **Ottava (8va/15ma/8vb/15mb) Write Mode Offset Bug:** In Write Mode (`Shift+W`), when an octave shift line (`8va`, `15ma`, `8vb`, `15mb`) is visually active on the staff, clicking to insert a note calculates the pitch based solely on the visual staff step, disregarding the active octave displacement. For example, when an `8va` line is displayed over the treble staff (`trebleShift = -7`), clicking the E5 space inserts E5 instead of the musically correct E6.

### 1.2 Current Technical State

* **History State Engine:** `NotationCanvas.tsx` maintains two local React refs (`undoStack` and `redoStack`) storing arrays of `ActiveNoteData[]`. The current `undo()` and `redo()` functions mutate `activeNotes.current` and call `updateSpellings()` and `recalculateLayout()`, but omit calling `forceUpdate()`, preventing React from rendering the restored state. Furthermore, keyboard event matching for `Z` / `Y` is sensitive to CapsLock and Shift-key casing, and the `APP_HISTORY` event listener lacks case-insensitive action normalization.
* **Octave Shift Layout Logic:** `recalculateLayout()` computes `trebleShift` (`-7` for `8va`, `-14` for `15ma`) and `bassShift` (`+7` for `8vb`, `+14` for `15mb`) as transient local variables inside its layout evaluation block. Because these values are not persisted to a component-level ref, `snapGhostNote()` and Write Mode click handlers cannot inspect the active staff displacement when translating cursor Y-coordinates (`visualStep`) into musical pitches (`musicalStep`).

## 2. Technical Decisions & Dependencies

### 2.1 Architectural Decisions & Scope

* **Zero Architectural Drift:** We strictly clone and extend the existing `ActiveNoteData` structure, `calculateWriteModePitch()` utility, and `commitState()` pattern without introducing new state libraries or external dependencies.
* **Component-Level Ref for Staff Shifts:** We introduce a persistent React ref (`activeStaffShiftsRef`) in `NotationCanvas.tsx` to store the latest evaluated `trebleShift` and `bassShift` step offsets from `recalculateLayout()`.
* **Separation of Visual Step vs. Musical Step:**
* `visualStep`: The raw step offset on the Grand Staff calculated from mouse Y-coordinates (`0` = Middle C line, `+9` = top E5 space of treble staff).
* `musicalStep`: The true musical step offset from Middle C, calculated as `visualStep - activeShift`.
* `ActiveNoteData.stepOffset`: Always stores the un-shifted **musical step offset**. The visual display displacement (`finalStep = stepOffset + shift`) is handled exclusively during layout rendering.



### 2.2 Mathematical Formulas & Pseudo-Code

#### Write Mode Ottava Displacement Formula

When the cursor hovers over or clicks the Grand Staff in Write Mode:

1. Identify the target staff region from the visual step:

$$\text{isTrebleStaff} = (\text{visualStep} \ge 0)$$


2. Lookup the active octave shift step displacement for that staff:

$$\text{activeShift} = \begin{cases} \text{activeStaffShiftsRef.current.trebleShift}, & \text{if } \text{isTrebleStaff} \\ \text{activeStaffShiftsRef.current.bassShift}, & \text{otherwise} \end{cases}$$


3. Calculate the true musical step offset:

$$\text{musicalStep} = \text{visualStep} - \text{activeShift}$$



*(Note: Since `trebleShift` is negative for `8va`/`15ma`, subtracting a negative number increases the step offset; e.g., $\text{visualStep } 9 - (-7) = \text{musicalStep } 16$, which corresponds to E6).*

#### Undo/Redo State Reconciliation Pseudo-Code

```typescript
const undo = () => {
  if (undoStack.current.length > 0) {
    redoStack.current.push(activeNotes.current.map(n => ({ ...n })));
    activeNotes.current = undoStack.current.pop() || [];

    chordIdentityRef.current.isActive = false;
    updateSpellings();
    updateActiveNotes?.([...activeNotes.current]);
    recalculateLayout();
    forceUpdate(); // MANDATORY: Trigger synchronous React re-render
  }
};

```
