# Product Requirements Prompt (PRP) — 12-Bar Sequencer & Viewport 🔘

## 1. Project Context & Objectives
We are expanding the `StepSequencer` timeline from 8 bars to 12 bars. Because 12 bars will compress the notation horizontally and make it illegible, we must introduce a scrollable viewport. The left-hand column (containing the clefs and braces) must remain frozen/sticky, while the 12 measures scroll horizontally. Additionally, we need to ensure the viewport automatically scrolls to keep the playhead in view during recording and keyboard navigation.

## 2. Technical Decisions & Dependencies
* **Target File:** `src/plugins/chord-notator/components/StepSequencer.tsx`.
* **State Expansion:** All hardcoded instances of `8` and `7` (index limits) will be updated to `12` and `11`.
* **Data Migration:** The `localStorage` initialization must be patched to pad existing 8-bar saves with 4 empty bars so users do not lose their current work upon upgrading.
* **Layout Approach:** The flex container will be split. The Clef column will remain `flex-shrink-0`, and the `sequence.map` loop will be wrapped in a new `div` with `overflow-x-auto`, `flex-1`, and `flex`. The individual measures will get a `min-w-[110px]` to prevent squashing.
* **Auto-Scroll:** We will use `scrollIntoView({ behavior: 'smooth', inline: 'nearest' })` triggered by changes to `currentStep` or `selectedStep`.

## 3. Implementation Phases

### Phase 1: State Expansion & Migration (`StepSequencer.tsx`) — 🔘
* **Objective:** Update the data model to support 12 bars safely.
* **Instructions:**
  1. In the `useState` initialization for `sequence`, update the `localStorage` check:
     ```javascript
     if (Array.isArray(parsed)) {
       if (parsed.length === 12) return parsed;
       // Migrate legacy 8-bar saves
       if (parsed.length === 8) return [...parsed, ...Array(4).fill({ notes: [], symbol: '' })];
     }
     ```
  2. Update the default fallback array: `return Array(12).fill({ notes: [], symbol: '' });`
  3. Locate the Trash Can `onClick` handler. Update the clear function: `setSequence(Array(12).fill({ notes: [], symbol: '' }));`
  4. In the `ArrowLeft`/`ArrowRight` keyboard event listener, update the boundary check from `if (nextStep > 7)` to `if (nextStep > 11)`.
  5. In the `handleMidi` NoteOff advancement logic, change `if (s >= 7)` to `if (s >= 11)`.

### Phase 2: Viewport Layout & Frozen Clef (`StepSequencer.tsx`) — 🔘
* **Objective:** Restructure the DOM to support horizontal scrolling while keeping the clefs visible.
* **Instructions:**
  1. Locate the container wrapping the Clef Column and the 8 bars: `<div className="flex-1 flex border... overflow-hidden">`
  2. Add a right-side shadow to the Clef Column to visually separate it from scrolling content: `className="... z-20 shadow-[4px_0_8px_rgba(0,0,0,0.05)] border-r border-black/30 dark:border-gray-600/50"`
  3. **Wrap the `sequence.map` output** in a new scrolling container:
     ```javascript
     <div className="flex-1 flex overflow-x-auto scrollbar-thin scrollbar-thumb-gray-300 dark:scrollbar-thumb-gray-700">
       {sequence.map((bar, idx) => ( ... ))}
     </div>
     ```
  4. On the individual bar wrapper (inside the map), add `min-w-[100px] flex-shrink-0` to the class list so the bars maintain their width and trigger the scroll overflow.
* **TDD Checkpoint:** * **Test Case 1:** [Given a 12-bar sequence, Assert the horizontal scrollbar appears and the Clef column remains fixed on the left when scrolling].
  * **Status Update:** "Transition Phase status to 🔵 Active. Refactor the DOM. Once verified visually, update to ✅ Completed."

### Phase 3: Playhead Auto-Scroll (`StepSequencer.tsx`) — 🔘
* **Objective:** Ensure the active bar (either recording or selected) is always visible in the viewport.
* **Instructions:**
  1. Add an `id` to the individual bar wrapper inside the map: `id={`seq-bar-${idx}`}`
  2. Implement a new `useEffect` that triggers when `currentStep` or `selectedStep` changes:
     ```javascript
     useEffect(() => {
       const activeIndex = selectedStep !== null ? selectedStep : currentStep;
       const activeElement = document.getElementById(`seq-bar-${activeIndex}`);
       if (activeElement) {
         activeElement.scrollIntoView({ behavior: 'smooth', block: 'nearest', inline: 'nearest' });
       }
     }, [currentStep, selectedStep]);
     ```
* **TDD Checkpoint:** * **Test Case 1:** [Given the viewport is scrolled to bar 1, When the `selectedStep` is changed to 11 via arrow keys, Assert the container automatically scrolls to bring bar 11 into view].
  * **Status Update:** "Transition Phase status to 🔵 Active. Implement the auto-scroll. Once passing, update to ✅ Completed."
  * **User Verification:** "[USER VERIFICATION REQUIRED] Pause for user review. Start recording and play chords until you pass bar 6. Confirm the viewport automatically scrolls to keep the red playhead visible."
