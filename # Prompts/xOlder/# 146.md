# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives

### 1.1 Summary of Objectives

The **VV | MIDI Chord Notator & Sequencer** suite (`src/plugins/chord-notator/`) includes an expandable 12-bar step sequencer (`src/plugins/chord-notator/components/StepSequencer.tsx`). While compact mode (`!isExpanded`, 140px height) operates as a timeline overview, expanded mode (`isExpanded`, 320px height) is designed to serve as a full-scale notation editor. Currently, three defects in expanded mode degrade visual parity and interactive audio feedback:

1. **Notation Scale Disparity:** In expanded mode, the notation staff scale (`miniStaff = 11`) is smaller than the primary notation canvas (`DEFAULT_STAFF_SPACE_PX = 12` in `NotationCanvas.tsx`). As a result, staff lines, clefs, noteheads, accidentals, and ledger lines do not match the exact dimensions and proportions of the main canvas.
2. **Incorrect Cursor Styling:** In expanded mode, the staff canvas area applies `cursor-crosshair`. It must remain the standard default pointer (`cursor-default` on the staff background, `cursor-pointer` on interactive elements), identical to `NotationCanvas.tsx`.
3. **Chord Card Playback Bug in Expanded Mode:** Clicking a chord symbol pill at the top of a step column in expanded mode plays the chord with an artificially short duration and can trigger unintended pitch mutations or low-register notes.

### 1.2 Current Technical State & Root Cause Analysis

* **Scale Parity (`miniStaff`):** In `StepSequencer.tsx`, `miniStaff` is declared as `const miniStaff = isExpanded ? 11 : 5;`. Because all glyph sizes, staff line offsets, accidental spacings, and ledger line widths are multiplied by `miniStaff`, using `11` instead of `12` causes a ~8.3% visual downscaling compared to `NotationCanvas.tsx` (`--staff-space: 12px`). Additionally, ledger lines render with `h-[1px]` rather than the established `h-[1.5px]`.
* **Cursor Style:** Line 583 of `StepSequencer.tsx` explicitly assigns `cursor-crosshair` to `.staff-canvas-area`:
```tsx
<div data-staff-area={idx} className="flex-1 relative w-full h-full staff-canvas-area cursor-crosshair"

```


* **Chord Card Playback Root Cause:** In `StepSequencer.tsx`, chord symbol pills are rendered as `<div>` elements (not `<button>` elements). When a user clicks a chord pill in expanded mode (`isExpanded === true`):
1. The chord pill's `onPointerDown` fires and calls `audioEngine.noteOn(...)`.
2. Because the click event bubbles up to the sequencer scroll container (`<div ref={seqCanvasRef} onPointerDown={handlePointerDown} ...>`), `handlePointerDown` executes.
3. In compact mode, `handlePointerDown` exits early via `if (!isExpanded) return;`. In expanded mode, however, `handlePointerDown` continues because the target is neither a `'button'` nor a `'[data-seq-note]'`.
4. **The Short Duration Bug:** `seqCanvasRef.current` executes `e.currentTarget.setPointerCapture(e.pointerId);`, stealing pointer capture from the chord pill. The browser immediately fires `onPointerCancel` / `onPointerLeave` on the chord pill, which calls `audioEngine.releaseNote(...)` only milliseconds after note-on.
5. **The Low Register / Pitch Mutation Bug:** If Write Mode (`isWriteMode`) is active, `handlePointerDown` on `seqCanvasRef` invokes `snapTimelineGhostNote(clickY, ...)` using the chord pill's Y-coordinate at the very top of the bar (`pointerY < 0`). This calculates an extremely low step offset (e.g., C1 / MIDI 24), inserts that unintended low pitch into the step sequence, and plays a 500ms preview.

## 2. Technical Decisions & Dependencies

### 2.1 Architectural Decisions & Zero-Drift Alignment

* **Exact Mathematical Parity:** We standardize `miniStaff` in expanded mode to `12` (`const miniStaff = isExpanded ? 12 : 5;`), matching `DEFAULT_STAFF_SPACE_PX` (`12px`) in `NotationCanvas.tsx`.
* **Explicit Hitbox Attribute Identification:** We add `data-chord-pill="true"` to the chord symbol pill container and include it in the early-exit guard of `seqCanvasRef`'s `handlePointerDown`:
```typescript
const target = e.target as HTMLElement;
if (
  target.closest('button') || 
  target.closest('[data-seq-note]') || 
  target.closest('[data-chord-pill]')
) {
  return;
}

```


* **No `e.stopPropagation()` Collisions:** In accordance with our Architectural Guidelines, we **do not** add `e.stopPropagation()` to note hitboxes or chord pills to block Write Mode clicks. Instead, `seqCanvasRef` explicitly filters out clicks originating inside `[data-chord-pill]`, `button`, and `[data-seq-note]`.
* **Reliable Pill Pointer Capture:** In the chord symbol pill's `onPointerDown` handler, we explicitly call `e.currentTarget.setPointerCapture(e.pointerId)` for standard selection clicks so the pill retains capture until `onPointerUp`, guaranteeing clean sustain on press/hold.
