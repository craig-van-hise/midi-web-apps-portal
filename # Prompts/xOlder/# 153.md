# Product Requirements Prompt (PRP) — [Status Marker] 🔘

## 1. Project Context & Objectives

### 1.1 Summary of Objectives

The **VV | MIDI Chord Notator & Sequencer** suite (`src/plugins/chord-notator/`) currently suffers from a destructive voice-erasure bug during note doubling and polyphonic voice crossing. When a user transposes a lower voice upward (by semitone, diatonic step, or rotation) so that its pitch collides with and crosses an upper voice, the application deletes the colliding voice or forces both voices to merge into a single pitch.

We must upgrade the notation engine and step sequencer to:

1. **Support Non-Destructive Voice Crossing:** Allow independent polyphonic voices to traverse through one another during chromatic, diatonic, and rotation transformations without deleting, merging, or reordering voices.
2. **Preserve Doubled Voices (True Unisons):** Retain all note objects in the chord array when multiple voices share the exact same MIDI pitch number.
3. **Ensure Full Canvas & Sequencer Parity:** Guarantee non-destructive voice preservation across both the primary notation canvas (`src/plugins/chord-notator/components/NotationCanvas.tsx`) and the 12-bar step sequencer (`src/plugins/chord-notator/components/StepSequencer.tsx`).



### 1.2 Current Technical State & Root Cause Analysis

* **Why Crossing a Voice Caused Voice Deletion (`enforcePianoRange` in `notationMath.ts`):**
* When a note transformation occurs in `NotationCanvas.tsx` (`applyChromaticShift`, `applyDiatonicShift`, or `applyPcsRotation`), the code maps `activeNotes.current` to an array of `proposedPitches` and passes it to `enforcePianoRange(proposedPitches, originalPitches)`.


* Currently, `enforcePianoRange` executes:


```typescript
const cleaned = proposedNotes.map(n => Number(n)).filter(n => !isNaN(n));
return Array.from(new Set(cleaned)).sort((a, b) => a - b);

```


* **The Critical Architectural Flaw:** `enforcePianoRange` wraps `cleaned` in `new Set(...)` (stripping duplicate pitches) and executes `.sort((a, b) => a - b)` (reordering the array ascending).


* Because `safePitches = enforcePianoRange(proposedPitches, originalPitches)` is sorted, when Voice 0 (`60`) is transposed up to `65` (crossing Voice 1 at `64`), `proposedPitches = [65, 64]` is sorted to `safePitches = [64, 65]`.


* In the subsequent `updatedNotes.map`, Voice 0 is assigned `safePitches[0]` (`64`), while Voice 1 (unselected) remains `note: 64`. Both voices become `64`. Furthermore, if any deduplication (`seenPitches` or `new Set()`) runs, the second voice is immediately discarded.




* **Why Refresh Events Wiped Doubled Voices (`handleMidiMessage` in `NotationCanvas.tsx`):**
* When `MIDI_MESSAGE_RECEIVED` with `{ refresh: true, notes }` arrives, `NotationCanvas.tsx` currently calls `enforcePianoRange(itemPitches, [])` (which strips duplicates via `new Set`) and uses `.find(...)` to map pitches back to note objects:


```typescript
const existing = notes.find((item: any) => (typeof item === 'object' ? item.note : item) === pitch);

```


* Because `.find(...)` always returns the first matching element, doubled pitches collapse into a single reference.




* **Unison Layout Collisions (`assignXLevels` in `notationMath.ts`):**
* When true unisons (`ySteps` and `note` are identical) are split into `leftStack` and `rightStack`, `assignXLevels` currently executes `group[i].forceAccidentalDisplay = true;` on the right-column note. True unisons must render side-by-side (`xLevel = 0` and `isRightColumn = true`) without forcing unnecessary accidental glyphs.

## 2. Technical Decisions & Dependencies

### 2.1 Architectural Decisions & Zero-Drift Alignment

* **Remove Deduplication and Sorting from `enforcePianoRange`:** `enforcePianoRange` must act strictly as an 88-key range validator (`21 <= n <= 108`). It must return `proposedNotes` in its exact original order without applying `new Set(...)` or `.sort(...)`, preserving 1-to-1 index alignment with `activeNotes.current`.


* **Strip All `seenPitches` Deduplication Filters:** We remove `seenPitches` filtering loops from `applyChromaticShift`, `applyDiatonicShift`, and `applyPcsRotation` in `NotationCanvas.tsx`. Every note object retains its unique `id` (`crypto.randomUUID()`) and remains in `activeNotes.current` regardless of unison collisions.


* **Preserve Objects Directly on `{ refresh: true }`:** When `handleMidiMessage` receives `{ refresh: true, notes }` in `NotationCanvas.tsx`, we map directly over `notes` without calling `enforcePianoRange` or `.find(...)`, guaranteeing zero voice loss during external state updates.



### 2.2 Mathematical Formulas & Pseudo-Code Specifications

#### 88-Key Range Validation Without Index Scrambling (`notationMath.ts`)

```typescript
export const enforcePianoRange = (proposedNotes: number[], originalNotes: number[]): number[] => {
  const isOutOfBounds = proposedNotes.some(n => {
    const num = Number(n);
    return isNaN(num) || num < 21 || num > 108;
  });
  
  if (isOutOfBounds) {
    if (originalNotes.length > 0) {
      return originalNotes;
    }
    // For fresh out-of-bounds inputs, filter invalid pitches without sorting
    return proposedNotes.map(n => Number(n)).filter(n => !isNaN(n) && n >= 21 && n <= 108);
  }
  
  // MANDATORY: Return array in original order without new Set() or .sort()
  return proposedNotes.map(n => Number(n)).filter(n => !isNaN(n));
};

```

#### Non-Destructive Polyphonic Transformation (`NotationCanvas.tsx`)

```typescript
// Inside applyChromaticShift, applyDiatonicShift, and applyPcsRotation:
const updatedNotes = activeNotes.current.map((noteData) => {

  return {
    ...noteData,
    note: safePitches[index],
    sourceMidi: safePitches[index],

  };
});

// DIRECT ASSIGNMENT: ZERO DEDUPLICATION OR VOICE ERASURE
activeNotes.current = updatedNotes;

const newSelection = new Set<string>();
updatedNotes.forEach(noteData => {

    newSelection.add(noteData.id);
  }
});
selectedNoteIds.current = newSelection;

```
