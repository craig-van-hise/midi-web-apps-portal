# Product Requirements Prompt (PRP) — [Status Marker] 🔘

## 1. Project Context & Objectives

### 1.1 Summary of Objectives

The **VV | MIDI Chord Notator & Sequencer** suite (`src/plugins/chord-notator/`) currently suffers from a voice-erasure defect during note doubling and voice crossing. When a user transposes a selected note (e.g., shifting a lower voice up by semitone or diatonic step) and its pitch collides with or crosses another existing note in the chord, the application deletes the colliding voice. This permanently reduces the polyphonic voice count of the chord (e.g., shrinking a 3-voice chord to 2 voices).

We must upgrade the notation engine and step sequencer to:

1. **Preserve Doubled Voices (Unisons):** Retain all note objects in the chord array when multiple voices share the exact same MIDI pitch number.
2. **Support Polyphonic Voice Crossing:** Allow independent voices to traverse through one another during chromatic, diatonic, or rotation transformations without deleting or merging overlapping note entries.
3. **Ensure Bi-Directional Parity:** Apply polyphonic voice preservation across both the primary interactive canvas (`src/plugins/chord-notator/components/NotationCanvas.tsx`) and the 12-bar step sequencer timeline (`src/plugins/chord-notator/components/StepSequencer.tsx`).



### 1.2 Current Technical State & Root Cause Analysis

* **Pitch Deduplication Filter in `NotationCanvas.tsx`:** In L154–L165, L221–L232, and L327–L338 of `NotationCanvas.tsx`, the transformation handlers (`applyChromaticShift`, `applyDiatonicShift`, and `applyPcsRotation`) explicitly strip duplicate pitches after computing transformation shifts:


```typescript
const uniqueNotes: typeof updatedNotes = [];
const seenPitches = new Set<number>();
updatedNotes.forEach(noteData => {
  if (!seenPitches.has(noteData.note)) {
    seenPitches.add(noteData.note);
    uniqueNotes.push(noteData);
  }
});
activeNotes.current = uniqueNotes;

```


Because `seenPitches` drops any `noteData` whose target MIDI pitch matches an already-processed voice, transposing one note into unison with another permanently destroys the second voice object.


* **Unison Visual Layout in `notationMath.ts`:** In `assignXLevels(notes: NotePosition[])` (L232–L271 of `notationMath.ts`), notes are grouped by `ySteps` to separate flattest-to-sharpest chromatic collisions into left and right columns. When two notes share the exact same MIDI pitch (true unison), they share the same `ySteps`. Currently, `leftStack.push(group[0])` and `rightStack.push(group[i])` assign the second unison note to `isRightColumn = true`. We must ensure true unisons receive distinct horizontal X-offsets (`NOTE_OFFSET_X_PX + PADDING_PX`) without requiring accidental padding so both noteheads render side-by-side and remain independently clickable.


* **Step Sequencer Array Handling (`StepSequencer.tsx`):** In `StepSequencer.tsx`, each bar's `notes` property stores an array of note objects (`{ id, note, stepOffset, isTreble, accidental }`). When `handleVoicePreservingNavigation` or marquee drag selection operates on step chords, we must ensure voice selection tracks by unique note `id` rather than raw MIDI pitch numbers so individual doubled voices can be selected and edited independently.

## 2. Technical Decisions & Dependencies

### 2.1 Architectural Decisions & Zero-Drift Alignment

* **Remove Deduplication Filters:** We strictly remove `seenPitches` deduplication sets from `applyChromaticShift`, `applyDiatonicShift`, and `applyPcsRotation` in `NotationCanvas.tsx`. Every note object in `activeNotes.current` retains its stable `id` (`crypto.randomUUID()`) and remains in the array regardless of pitch collisions.


* **ID-Based Selection Tracking:** We enforce that `selectedNoteIds.current` (`Set<string>`) is the canonical source of truth for UI selection. When rendering note containers in `NotationCanvas.tsx` and `StepSequencer.tsx`, DOM elements must expose `data-id={note.id}` alongside `data-note-id={note.note}` so click and marquee hit-tests can resolve specific voice instances even when MIDI pitches are doubled.


* **Side-by-Side Unison Rendering:** In `assignXLevels` (`src/plugins/chord-notator/utils/notationMath.ts`), when multiple notes share identical `ySteps` and identical `note` pitches, the layout engine assigns `xLevel = 0` to the first voice and `xLevel = 1` (`xOffset = NOTE_OFFSET_X_PX + PADDING_PX`) to the second voice, ensuring both noteheads are visually legible.



### 2.2 Mathematical Formulas & Pseudo-Code Specifications

#### Polyphonic Transformation without Voice Erasure (`NotationCanvas.tsx`)

```typescript
// Replaces the seenPitches deduplication block in applyChromaticShift,
// applyDiatonicShift, and applyPcsRotation:

const updatedNotes = activeNotes.current.map((noteData) => {
  const isSelected = selectedNoteIds.current.has(noteData.id);
  if (!isSelected) return noteData;
  const index = activeNotes.current.findIndex(n => n.id === noteData.id);
  return {
    ...noteData,
    note: safePitches[index],
    sourceMidi: safePitches[index],
    spellingOverride: undefined
  };
});

// PRESERVE ALL VOICES (INCLUDING UNISONS & DOUBLINGS):
activeNotes.current = updatedNotes;

// Maintain existing selection IDs cleanly across transformations:
const newSelection = new Set<string>();
updatedNotes.forEach(noteData => {
  if (selectedNoteIds.current.has(noteData.id)) {
    newSelection.add(noteData.id);
  }
});
selectedNoteIds.current = newSelection;

```

#### True Unison X-Level Zipper Assignment (`notationMath.ts`)

When calculating layout offsets for `rawNotes` in `assignXLevels(notes: NotePosition[])`:


$$\Delta X_{\text{unison}} = \text{staffSpace} \times 1.2 + \text{padding}$$

```typescript
// In assignXLevels, group by ySteps:
const groups: Record<number, NotePosition[]> = {};
notes.forEach(n => {
  if (!groups[n.ySteps]) groups[n.ySteps] = [];
  groups[n.ySteps].push(n);
});

const leftStack: NotePosition[] = [];
const rightStack: NotePosition[] = [];

Object.values(groups).forEach(group => {
  if (group.length > 1) {
    // Sort flattest to sharpest; for identical pitches, preserve array insertion order
    group.sort((a, b) => (a.note || 0) - (b.note || 0));
    leftStack.push(group[0]);
    for (let i = 1; i < group.length; i++) {
      // Only force accidental display if the pitch is chromatically distinct from group[0]
      if (group[i].note !== group[0].note) {
        group[i].forceAccidentalDisplay = true;
      }
      group[i].isRightColumn = true;
      rightStack.push(group[i]);
    }
  } else {
    leftStack.push(group[0]);
  }
});

```
