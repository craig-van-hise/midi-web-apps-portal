# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives

### 1.1 Summary of Objectives

We have validated that **Marquee Drag Selection** and the **500ms Self-Terminating Audio Preview Timer** in `StepSequencer.tsx` and `NotationCanvas.tsx` are operating as intended. However, testing of **PRP #149 (Chunk 3)** revealed two critical usability and state-synchronization defects in `src/plugins/chord-notator/components/StepSequencer.tsx`:

1. **Undo/Redo State Desynchronization (Mouse-Move Reset Bug):** When a user transposes a chord in the expanded step sequencer and presses `Cmd+Z` / `Ctrl+Z`, the visual timeline initially restores the untransposed chord. However, moving the mouse across the canvas immediately resets the step back to the transposed chord.
2. **Missing Canvas Click-Away Deselection:** In `NotationCanvas.tsx`, clicking empty staff space away from noteheads deselects all currently selected notes. In `StepSequencer.tsx`, clicking empty staff space initiates marquee selection tracking but fails to clear existing note selections when no modifier keys (`Shift`, `Cmd`/`Ctrl`, `Alt`) are pressed.

### 1.2 Root Cause Analysis

* **Why Moving the Mouse Resets Undo (`StepSequencer.tsx`):**
* When `APP_TRANSFORM` occurs, `NotationCanvas.tsx` transposes its local `activeNotes.current` and calls `updateActiveNotes([...activeNotes.current])`. This updates `MIDIProvider` state and broadcasts a custom `MIDI_MESSAGE_RECEIVED` event with `{ refresh: true, notes: activeNotes }`.
* When `undoSeq()` runs in `StepSequencer.tsx`, it pops the previous sequence snapshot from `seqUndoStack` and calls `setSequence(prev)`.
* **The Architectural Flaw:** `undoSeq()` and `redoSeq()` **do not call `updateActiveNotes**`. Consequently, `MIDIProvider` and `NotationCanvas.tsx` still hold the transposed chord in their active state. When a mouse movement or hover event triggers a re-render or status check, `StepSequencer.tsx` receives a state refresh from `MIDIProvider` containing the transposed chord, overwriting the undone sequence bar.


* **Why Clicking Away Does Not Deselect (`StepSequencer.tsx`):**
* In `handlePointerDown` on `seqCanvasRef` (around line 335 of `StepSequencer.tsx`), clicking `.staff-canvas-area` initializes `dragTracker.current` for marquee selection. It does not check whether a selection already exists or clear `selectedNotes` when clicking without modifier keys.

## 2. Technical Decisions & Dependencies

### 2.1 Architectural Decisions & Zero-Drift Alignment

* **Upstream State Synchronization on Sequencer Undo/Redo:** Whenever `undoSeq()` or `redoSeq()` is invoked in `StepSequencer.tsx`, the function must inspect `selectedStepRef.current`. If a step is active (`selectedStepRef.current !== null`), it must immediately call `updateActiveNotes(prev[activeStep].notes, true, false, [])` to push the restored historical notes upstream to `MIDIProvider` and `NotationCanvas.tsx`.
* **Standard Click-Away Deselection:** In `handlePointerDown` on `seqCanvasRef`, if the user clicks an empty staff area without holding `Shift`, `Cmd`/`Ctrl`, or `Alt`, we immediately invoke `updateActiveNotes(sequence[startStep].notes, true, false, [])`. This clears `selectedNotes` to `[]` while preserving the bar's note data, matching `NotationCanvas.tsx`.

### 2.2 Pseudo-Code Specifications

#### Sequencer Undo/Redo Upstream Synchronization (`StepSequencer.tsx`)

```typescript
const undoSeq = () => {
  if (seqUndoStack.current.length === 0) return;
  const prev = seqUndoStack.current.pop()!;
  seqRedoStack.current.push(JSON.parse(JSON.stringify(sequenceRef.current)));
  setSequence(prev);

  // MANDATORY UPSTREAM SYNC: Push restored notes to MIDIProvider & NotationCanvas
  const activeIdx = selectedStepRef.current;
  if (activeIdx !== null && prev[activeIdx]) {
    updateActiveNotes(prev[activeIdx].notes, true, false, []);
  }
};

const redoSeq = () => {
  if (seqRedoStack.current.length === 0) return;
  const next = seqRedoStack.current.pop()!;
  seqUndoStack.current.push(JSON.parse(JSON.stringify(sequenceRef.current)));
  setSequence(next);

  // MANDATORY UPSTREAM SYNC: Push restored notes to MIDIProvider & NotationCanvas
  const activeIdx = selectedStepRef.current;
  if (activeIdx !== null && next[activeIdx]) {
    updateActiveNotes(next[activeIdx].notes, true, false, []);
  }
};

```

#### Canvas Click-Away Deselection (`StepSequencer.tsx`)

```typescript
const handlePointerDown = (e: React.PointerEvent) => {
  if (e.button !== 0) return;
  if (!isExpanded) return;
  const target = e.target as HTMLElement;
  if (
    target.closest('button') || 
    target.closest('[data-seq-note]') || 
    target.closest('[data-chord-pill]')
  ) {
    return;
  }

  // ... existing Write Mode handling ...

  const rect = seqCanvasRef.current?.getBoundingClientRect();
  if (!rect) return;

  const clickX = e.clientX;
  const clickY = e.clientY;
  const elem = typeof document.elementFromPoint === 'function' ? document.elementFromPoint(clickX, clickY) : null;
  const stepEl = elem?.closest('[data-step-index]');
  let startStep = -1;
  if (stepEl) {
    startStep = parseInt(stepEl.getAttribute('data-step-index') || '', 10);
  }
  
  if (startStep === -1) return;

  // PARITY WITH NOTATION CANVAS: Deselect notes when clicking away without modifiers
  const hasModifier = e.shiftKey || e.metaKey || e.ctrlKey || e.altKey;
  if (!hasModifier && sequence[startStep]) {
    updateActiveNotes(sequence[startStep].notes, true, false, []);
  }

  e.currentTarget.setPointerCapture(e.pointerId);
  // ... continue initializing marquee dragTracker ...
};

```
