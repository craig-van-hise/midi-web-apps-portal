# Product Requirements Prompt (PRP) — Timeline Hitboxes & Marquee 🔘

## 1. Project Context & Objectives
The direct note manipulation on the `StepSequencer` timeline has two UX issues:
1. **Hitbox Overlap:** Clicking any note in a chord always selects the same single note. This is because the outer note wrapper `<div>` encompasses wide ledger lines and accidentals, causing the highest `z-index` wrapper to steal all pointer events for that column.
2. **Missing Marquee:** Users cannot click-and-drag to select multiple notes on the timeline.

We will isolate the pointer events directly to the SMuFL notehead `<span>` to fix the overlap, and implement a localized marquee selection overlay on the timeline grid.

## 2. Technical Decisions & Dependencies
* **Target File:** `src/plugins/chord-notator/components/StepSequencer.tsx`.
* **Hitbox Isolation:** Remove pointer event logic from the note wrapper `<div>` and attach it exclusively to the notehead `<span>`.
* **Marquee Architecture:** We will use `getBoundingClientRect()` to detect collisions between a dynamic marquee `<div>` and the notehead spans (which will be tagged with data attributes). The marquee will only select notes belonging to the step where the drag originated.

## 3. Implementation Phases

### Phase 1: Hitbox Precision (`StepSequencer.tsx`) — 🔘
* **Objective:** Ensure clicks are registered exclusively on the noteheads, not their surrounding invisible bounds.
* **Instructions:**
  1. Locate the absolute-positioned note wrapper `<div>` inside the `renderedNotes.map` loop (around line 431).
  2. **Remove** `pointer-events-auto`, `cursor-pointer`, and the `onPointerDown` handler from this outer `<div>`. Ensure the outer div has `pointer-events-none`.
  3. Move the `onPointerDown` handler, `pointer-events-auto`, and `cursor-pointer` directly to the inner `<span>` that renders `{SMuFL.noteheadWhole}`.
  4. Add data attributes to this inner notehead span for the marquee to target: `data-seq-note={n.note}` and `data-seq-step={idx}`.
     ```javascript

       data-seq-note={n.note}
       data-seq-step={idx}
       className={`transition-colors pointer-events-auto cursor-pointer ${textCol}`}

       onPointerDown={(e) => { ... existing handler ... }}
     >
       {SMuFL.noteheadWhole}
     </span>
     ```

### Phase 2: Marquee State & Overlay (`StepSequencer.tsx`) — 🔘
* **Objective:** Create the refs and DOM element for the drag window.
* **Instructions:**
  1. Add the following refs at the top of the component (near `const activeKeys = useRef(0);`):
     ```javascript
     const marqueeRef = useRef<HTMLDivElement>(null);
     const seqCanvasRef = useRef<HTMLDivElement>(null);
     const dragTracker = useRef({ isDragging: false, startX: 0, startY: 0, currentX: 0, currentY: 0, startStep: -1 });
     ```
  2. Attach `ref={seqCanvasRef}` to the scrolling `<div className="flex-1 flex overflow-x-auto ...">` container.
  3. Add the marquee DOM element as a child of that same container, ensuring it sits above the notes:
     ```javascript
     <div ref={marqueeRef} className="absolute border border-blue-500 bg-blue-500/20 z-50 pointer-events-none hidden" style={{ left: 0, top: 0, width: 0, height: 0 }} />
     ```

### Phase 3: Marquee Event Handlers (`StepSequencer.tsx`) — 🔘
* **Objective:** Implement the drag drawing and collision detection logic.
* **Instructions:**
  1. Add `onPointerDown`, `onPointerMove`, and `onPointerUp` (and `onPointerLeave`) handlers to the `seqCanvasRef` scrolling container.
  2. **PointerDown:** If the target isn't a button or existing notehead, record `startX`/`startY` (using `e.clientX` / `e.clientY`), set `isDragging = true`, and determine which bar (`startStep`) the user clicked in using `document.elementFromPoint` or closest data attribute. Set `selectedStep` to this bar.
  3. **PointerMove:** If `isDragging`, update `currentX`/`currentY`. Unhide the `marqueeRef` and draw the box using absolute positioning relative to the viewport or fixed coordinates (identical to the `NotationCanvas` marquee implementation).
  4. **PointerUp:** Hide the marquee. Get the `marqueeRect = marqueeRef.current.getBoundingClientRect()`. Query all spans matching `[data-seq-step="${dragTracker.current.startStep}"]`. Check if their `getBoundingClientRect()` intersects the `marqueeRect`.
  5. Collect all intersecting note pitches, and if the array is not empty, call `updateActiveNotes(sequence[startStep].notes, true, false, intersectingPitches)`.
