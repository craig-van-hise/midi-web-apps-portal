

# Product Requirements Prompt (PRP) — 🔘 Pending

## 1. Project Context & Objectives

### 1.1 Summary of Objectives

The **VV | MIDI Chord Notator & Sequencer** suite (`src/plugins/chord-notator/`) currently exhibits a **"Katamari" voice-catching defect** during polyphonic voice crossing. When a user selects an individual voice and transposes it across another voice in the chord, the moment the transposing voice reaches unison with an existing voice, the application selects **both** voices. Subsequent transpositions move all caught voices together, eventually collapsing the entire chord into a multi-note unison blob.

We must upgrade the notation canvas and step sequencer to:

1. **Enforce 1-to-1 Voice Selection Cardinality:** Replace greedy pitch-based selection matching (`if (targetSelection.includes(note.note))`) with 1-to-1 pitch-to-ID matching so that selecting or crossing into a unison pitch only selects the intended number of voice instances.
2. **Preserve Local ID Selection During Live Transformations:** Prevent `MIDI_MESSAGE_RECEIVED` refresh events from clobbering `selectedNoteIds.current` when those IDs are already present and valid in `activeNotes.current` during live canvas editing.
3. **Enable Non-Destructive Voice Crossing:** Allow any selected voice to transpose chromatically, diatonically, or via rotation *through* other voices in both `NotationCanvas.tsx` and `StepSequencer.tsx` without deleting, merging, or catching unselected voices.

### 1.2 Current Technical State & Root Cause Analysis

* **Greedy Pitch Matching in `NotationCanvas.tsx`:** In `handleMidiMessage` when `{ refresh: true, targetSelection }` is processed, the existing selection sync loop executes:
```typescript
if (targetSelection && targetSelection.length > 0) {
  selectedNoteIds.current.clear();
  activeNotes.current.forEach(note => {
    if (targetSelection.includes(note.note)) {
      selectedNoteIds.current.add(note.id);
      lastSelectedNoteId.current = note.id;
    }
  });
}

```


Because `targetSelection.includes(note.note)` returns `true` for **every** note object sharing that MIDI pitch number, transposing Voice 0 into unison with Voice 1 adds both `Voice 0` and `Voice 1` to `selectedNoteIds.current`.
* **Greedy Selection Highlighting in `StepSequencer.tsx`:** In the note rendering loop of `StepSequencer.tsx`, selection highlighting is evaluated as `const isNoteSelected = isStepSelected && selectedNotes?.includes(n.note);`. When two voices share the same MIDI pitch, both render as highlighted (`#aa3bff`), and clicking one hitbox toggles all unisons sharing that pitch.

## 2. Technical Decisions & Dependencies

### 2.1 Architectural Decisions & Zero-Drift Alignment

* **1-to-1 Pitch-to-Voice Cardinality Algorithm:** When translating external pitch arrays (`targetSelection` or `selectedNotes`) into selected note IDs, we must iterate through `targetSelection` and match each pitch to **at most one** unselected note object in `activeNotes.current`. If `targetSelection` contains `[64]`, exactly one voice at pitch `64` is selected; if it contains `[64, 64]`, two voices are selected.
* **ID-First Selection Retention:** During live keyboard or toolbar transformations on `NotationCanvas.tsx` (`applyChromaticShift`, `applyDiatonicShift`, `applyPcsRotation`), `selectedNoteIds.current` remains the canonical source of truth. When `updateActiveNotes` broadcasts a refresh event back to the canvas, the refresh handler must retain existing `selectedNoteIds.current` if all selected IDs remain valid in the updated note array.
* **Independent Hitbox Targeting in Step Sequencer:** In `StepSequencer.tsx`, clicking a note hitbox (`[data-seq-note]`) must toggle selection for that specific voice instance without greedily selecting all other voices that happen to share the same MIDI pitch number.

### 2.2 Mathematical Formulas & Pseudo-Code Specifications

#### 1-to-1 Cardinality Selection Matching (`NotationCanvas.tsx`)

$$\forall p \in \text{targetSelection}, \quad \exists! \, v \in \text{activeNotes} \text{ s.t. } v.\text{note} = p \land v.\text{id} \notin \text{newSelectedIds}$$

```typescript
// Replaces greedy targetSelection.includes(note.note) matching
// inside handleMidiMessage in NotationCanvas.tsx:

if (targetSelection && targetSelection.length > 0) {
  const newSelectedIds = new Set<string>();
  const availableNotes = [...activeNotes.current];
  
  targetSelection.forEach(targetPitch => {
    // Find the first matching voice that hasn't already been claimed
    const matchIdx = availableNotes.findIndex(
      n => n.note === targetPitch && !newSelectedIds.has(n.id)
    );
    if (matchIdx !== -1) {
      newSelectedIds.add(availableNotes[matchIdx].id);
      lastSelectedNoteId.current = availableNotes[matchIdx].id;
    }
  });
  
  selectedNoteIds.current = newSelectedIds;
}

```

#### Non-Catching Voice Transformation (`NotationCanvas.tsx`)

```typescript
// In applyChromaticShift, applyDiatonicShift, and applyPcsRotation:
const updatedNotes = activeNotes.current.map((noteData) => {
  const isSelected = selectedNoteIds.current.has(noteData.id);
  if (!isSelected) return noteData;
  
  // Mutate only the specifically selected voice ID:
  const index = activeNotes.current.findIndex(n => n.id === noteData.id);
  return {
    ...noteData,
    note: safePitches[index],
    sourceMidi: safePitches[index],
    spellingOverride: undefined
  };
});

activeNotes.current = updatedNotes;

// PRESERVE SELECTED IDs EXACTLY BY UNIQUE ID (NO PITCH CLOBBERING):
const newSelection = new Set<string>();
updatedNotes.forEach(noteData => {
  if (selectedNoteIds.current.has(noteData.id)) {
    newSelection.add(noteData.id);
  }
});
selectedNoteIds.current = newSelection;

```
